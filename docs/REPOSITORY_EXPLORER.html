Understand the repository

Use this guide to see how an idea becomes a reviewable project. It explains what each repository part does and where local checks stop. It is not a validator, audit, approval or deployment tool.

How the repository fits together
  1. SKILL.md sets the agent's behaviour
  2. Routing chooses which knowledge to load
  3. Schemas define the data shape
  4. Validators check whether the facts agree
  5. The compiler creates the project files
  6. Tests provide evidence for the exact inputs they run

    Limits of local checks

    What local checks can and cannot tell you

    Local checks can show

    Whether the schema is valid, fields are consistent, commands return expected results, hashes match, source files are complete and tested bytes behave reproducibly.

    Local checks cannot show

    Whether an independent auditor or maintainer will approve the work. They cannot grant signing authority, deploy or publish anything, or prove provider support, routing, tradability, indexing or public availability.

    This page is a dependency-free learning aid built from the repository's source files. If it disagrees with a machine contract, follow the schema and validator.
