prototype, trade-capability, or legacy Fee V2 evidence.

## Policy-neutral Proposal Draft fix

- An exactly valid Submission V2 at `stage: "proposal"` may materialize an Application V3.1 package when
  `ideaEligibility` remains `ELIGIBLE_FOR_REVIEW` and `feeApplicability` is `not-selected`.
- The proposal compatibility report must remain `architecture-review-required`.
- Proposal packages cannot contain a trade-capability manifest or trade-test result and cannot claim prototype
  readiness. Every legacy Fee V2 identity and instance field remains null.
- Selected or unresolved legacy Fee V2 proposals continue to fail closed. The absent-instance diagnostic now reports
  the actual field state.

availability, signing, routing, fund-handling, or launch authority, and it does not evaluate FADE or any other project.

The bundled `publicationStateVerified: false` status is not proof that Hookbuilder `v0.10.2` is public. Protected CI,
the immutable tag and release assets, attestations, public API visibility, and a fresh installation must be verified
independently after publication.
