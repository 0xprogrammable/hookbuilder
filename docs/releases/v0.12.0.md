# Programmable v4 Builder v0.12.0

This minor candidate lets Hookbuilder follow the current Submit Launch contract without copying changing policy values
into the Skill. It keeps application routing local, stage-specific, and fail-closed at every external write boundary.

## One current Submit Launch snapshot

- The resolver binds the canonical repository identity, protected branch, commit, tree, active contracts,
  compatibility contract, application and submission schemas, and launch policy from one Git tree.
- Its content-addressed cache is an optimization only. Build work can continue with an explicit unresolved-policy
  state, while submission, launch readiness, and production promotion require the applicable fresh snapshot.
- Resolved files remain inert data. Hookbuilder does not execute remote code or scan Website, Indexer, or unrelated
  repositories to decide what an Applicant must build.

## Current application routing

- Application V3.2, Submission V2.1, and Trade V2 are the current data contracts. V3.1 remains an isolated legacy
  input rather than a second source of current policy.
- A local adapter derives `no-market`, `external`, `unresolved`, or official Programmable Ethereum routing from the
  application and submission. Applicant input cannot mint an exemption, readiness result, or evidence status.
- Policy values such as fee BPS, recipient, rule text, and evidence pointers come from the resolved snapshot. A new
  structural contract shape still requires an explicit Builder adapter and versioned migration.

## Write and authority boundary

The submission path binds its snapshot, stage evaluation, and route projection to the confirmation plan, then checks
the protected head again before any GitHub mutation. Drift produces zero writes. A successful path can create or
update only an unreviewed Applicant Draft; it does not evaluate, accept, approve, audit, deploy, register, route, sign,
move funds, establish safety, or launch a project.

`v0.12.0` is not public merely because these notes or source bytes exist. As verified on 2026-08-20, the latest GitHub
Release is `v0.11.0`. The `v0.11.1` identity is tag-only, and `v0.11.2` is main-only. Protected CI, an immutable
`v0.12.0` tag, release assets, public API readback, and a fresh pinned installation remain separate evidence.
