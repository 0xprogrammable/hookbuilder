# Programmable v4 Builder v0.9.3

This patch release tightens the portable verifier's syntax inspection path without changing project, submission,
approval, deployment, or launch authority.

## Bounded module syntax inspection

- Portable `.mjs` files are parsed in one `SourceTextModule` worker instead of starting one Node child process per
  file.
- The worker performs syntax parsing only. It does not link imports, evaluate top-level code, or follow missing
  modules. A timeout, resource limit, invalid worker payload, or oversized diagnostic payload fails closed.
- Syntax diagnostics retain the inspected script path and bounded error text, so malformed source remains visible to
  the existing verifier without changing its repository or installed test gates.
- The generated Plugin payload and portable package receipts are regenerated from the canonical skill after the source
  change.
- The ambient temporary-directory regression now measures its own added and removed probe instead of assuming that no
  unrelated repository test changes the shared system temporary directory at the same time. Production containment
  attribution remains unchanged and still reports subject-linked out-of-lane writes.

## Measured local evidence

- On Node.js 24.14.0, three local runs over 334 portable `.mjs` scripts measured a median of 10,148 ms for the prior
  sequential `node --check` phase and 92 ms for the bounded worker phase. The measured phase is not a claim about
  total `npm test` time, model quality, or host behavior.
- Compared directly with the `v0.9.2` portable package, the inventory stays at 618 files and moves from 8,656,525 to
  8,657,625 bytes, an increase of 1,100 bytes for the bounded parser and its runtime metadata.
- Against the exact v0.9.1 Skill tree baseline of 686 files / 10,722,006 bytes, the portable source is 618 files /
  8,657,625 bytes, a local package inventory delta of 68 fewer files and 2,064,381 fewer bytes (-19.25%).
- The source inventory remains mechanically bound to 342 production modules and 10 local test files under
  `evals/tests`; the reference kernel inventory contains 54 unit, one fuzz and three invariant test functions.
- A static regression covers malformed syntax, missing imports, top-level await, and a write side effect. The side
  effect remains absent because the parser never links or evaluates the module.

## Authority boundary

Local checks and package generation remain `NOT_SUBMITTED` and `NOT_APPROVED`. The bundled
`publicationStateVerified: false` status is not proof of a public tag or installation. Passing the verifier is not an audit,
public CI result, maintainer approval, deployment, provider result, or launch authorization. The exact `v0.9.3` tag,
immutable GitHub Release, assets, protected CI and fresh installed bytes must be verified independently after any
publication.
