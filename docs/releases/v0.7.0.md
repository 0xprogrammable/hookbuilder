# Programmable v4 Builder v0.7.0

This release package moves current build and workflow-canary criteria to the central Submit a Launch policy,
quarantines retired bundled platform rules from present decisions, and adds a preview-only hidden canary application
client. It does not grant review, audit, approval, routing, launch, deployment, signing, GitHub-write, or funds authority.
At private candidate freeze, bundled lifecycle still reports `publicationStateVerified: false`; source bytes do not
prove that v0.7.0 is published or live.

## Central policy authority

- The Builder resolves the current policy and schema from `0xprogrammable/submit-launch`, numeric repository ID
  `1320171831`, required branch `main`.
- The golden path runs `cli.mjs policy` before context or construction and returns every active `build` Rule ID from
  those exact bytes. No bundled document can add a Programmable launch requirement.
- Every consuming boundary returns the exact repository, ref, commit, tree, path, byte length, and SHA-256 binding it
  used. A changed repository identity, required branch, head, tree, path, bytes, or digest fails closed.
- Frozen V1 records and retired V2 compatibility material remain available only as labeled historical evidence. They no
  longer decide current build or workflow-canary outcomes.
- The central policy is a shared machine-readable contract. This Builder consumes it now; a future reviewer or security
  service must independently implement and verify the same contract rather than inheriting Builder authority.

## Workflow canary

`prepare-canary` derives one canonical hidden workflow-canary Application V1 from the exact central policy and canary
schema. The default path returns the complete inert JSON bytes and their digest without writing a file. It resolves the
candidate's exact public repository, commit, and tree identity through bounded GitHub reads without requesting or
executing candidate source blobs. Caller-selected repositories, refs, schemas, builders, output namespaces, or approval
decisions cannot replace the fixed inputs.

Automated local writing remains fail-closed with `LOCAL_WRITE_UNAVAILABLE`; even an exact digest acknowledgement
performs zero filesystem mutation. The command performs no GitHub write and cannot review, audit, approve, discover,
route, launch, deploy, sign, or move value.
