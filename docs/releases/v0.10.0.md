# Programmable v4 Builder v0.10.0

This minor release activates the public Application V3 path for every complete Programmable project while preserving
the existing explicit-confirmation, draft-only, and protected-review boundaries.

## Universal public Applicant path

- Every complete `PROJECT_PREFLIGHT_VALID` project can materialize a closed Application V3 package and use the
  namespaced `open-world submit`, `update`, and `status` commands. The legacy top-level Applicant flow remains available
  only for its documented continuations.
- Application V3 advances to contract 3.1.0. Submission V2 is still required for every project. When Submission V2
  selects neither `programmableFee` nor the legacy Fee V2 schema, the application declares
  `feeApplicability: "not-selected"`, leaves every Fee V2 identity, hash, schema, and instance field null, and excludes
  `fee-policy-schema` from the required kinds and records.
- A read-only plan resolves the protected Submit a Launch base and binds its exact commit and tree, active-contract
  manifest path and bytes, and the declared and retrieved Application V3 schema bytes. Contract, manifest, schema, or
  source drift invalidates the plan instead of silently reusing its confirmation digest.
- The public central contract was read back at Submit a Launch `v1.6.0`: commit
  `e15b9288b485be9b28a3e6d1a048d35cdf7ed918`, tree
  `bb428bda6f239afe7fbbefc792bfe222916a3d58`, active-contract SHA-256
  `b22f3d79119f75c9912aa03966e3397528ff9ce264b694eaa49598e61a50dfd4`, and V3 schema SHA-256
  `2d51837bbbfe52672ecca334596243bebcec78e8e0a885d67084dfd98955bcb7`.

## Transport hardening

- Local package materialization opens each regular file with `O_NOFOLLOW`, snapshots the descriptor with `fstat`, and
  rejects identity, size, or timestamp changes across the bounded read. Symlink and replacement races fail closed.
- Pull-request normalization and final readback require GitHub `maintainer_can_modify: false`. Substituting `true`
  invalidates status, submit, update, and mutation reconciliation rather than broadening write authority.
- Public source, package, and contract bytes remain inert data. The transport does not execute candidate code or
  accept repository, branch, CI, publication, or credential instructions from project contents.

## Authority boundary

The command without `--confirm-external-write` performs only read-only GitHub requests and returns the exact
confirmation digest. A matching confirmation can create only the builder's public Submit a Launch fork, the bound
application branch, and one draft pull request. The Builder never marks that request ready, approves it, merges it,
deploys a project, signs a transaction, or grants launch authority.

The bundled `publicationStateVerified: false` status is not proof that Hookbuilder `v0.10.0` is public. Protected CI,
maintainer review, the immutable tag and release assets, attestations, public API visibility, and a fresh installation
must be verified independently after publication.
