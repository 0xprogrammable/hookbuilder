# Programmable v4 Builder v0.10.0

This release turns the Builder from a hook-only generator into a complete-project workflow while keeping launch,
approval, external execution, and publication authority separate.

## Complete projects continue into implementation

- A request can move from an accepted design into implementation without matching a bundled reference profile.
- Bounded caller-supplied contract, web, service, and game source trees can be preserved as inert project inputs. The
  surface labels describe owner intent; they are not a claim that an application has been executed, audited, or
  deployed.
- Generated plans and receipts bind the accepted regular-file bytes and generated project configuration. Candidate
  commands remain `NOT_RUN` until separately trusted execution evidence exists.

## Exact no-write submission handoff

- `handoff preview` produces lossless canonical handoff bytes for complete no-market, tradable, and multi-surface
  projects.
- The handoff derives active build requirements from the exact central policy and schema preimages and binds the
  protected Submit repository, base revision, application directory, source revision, project receipt, complete
  surface inventory, and intended draft pull-request identity.
- Preview performs no network or filesystem mutation. The portable write path rechecks its confirmation and then
  fails closed until a reviewed descriptor-bound external writer exists.

## Benchmarkable quality

- A versioned public journey corpus covers natural English and German requests, the reported design-to-implementation
  regression, adjacent non-trigger cases, malformed inputs, missing tools, unavailable authority, and adversarial
  repository behavior.
- The comparison harness keeps expected outcomes and rubrics out of subject requests, binds adapter requests and
  evidence, and records activation, references, repository output, efficiency, effects, and independent-judge
  results.
- Structural and fake-adapter checks are local regression evidence only. Provider-backed comparisons require the
  configured trusted sandbox and independent judge; none are implied by this source release.

## Smaller portable installation

- One manifest now defines the portable runtime closure used by Skill installation, plugin generation, release
  artifacts, size checks, and installed verification.
- Development tests remain in the full repository suite but are not copied into ordinary Skill installations.
- The installed package retains deterministic runtime smoke checks for CLI, routing, scaffolding, bounded inputs, and
  frozen compatibility behavior.

## Sandbox integration boundary

- Host operators receive a deterministic, networkless container invocation plan and explicit evidence contracts.
- The portable package does not ship a runner image, production launcher, trust root, signing key, or host authority.
  A caller-created key or locally fabricated receipt cannot establish completion.
- Real isolation, resource enforcement, teardown, trusted signing, and completion import remain external and must be
  independently verified.

## Authority boundary

Local source generation and handoff preparation remain `NOT_SUBMITTED` and `NOT_APPROVED`. Policy satisfaction and
passing tests are not an audit or automatic approval. Protected Submit a Launch and Website services retain
independent review, acceptance, deployment, routing, discovery, signing, real-funds, and launch authority.

The bundled state retains `publicationStateVerified: false`. Source, branch, local tests, or a release candidate do not
prove that the public `v0.10.0` tag, immutable GitHub Release, assets, protected CI, or installed bytes exist.
