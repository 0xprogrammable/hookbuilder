# Programmable v4 Builder v0.11.1

This patch repairs the normal Applicant journey for a project that already has one exact public Application V3.1 Draft
but has no v0.11 Applicant workspace or local application-package directory.

## Existing Draft recovery

- `submit-project <repository-root>` may find one open Applicant-owned Draft only through bounded read-only GitHub
  observations.
- Before it materializes any package data, recovery checks the fixed public Submit Launch repository, the active
  Applicant identity, public writable fork, exact Draft state, immutable Application title and revision, source commit
  and tree, and the selected Submission V2 path and SHA-256.
- It downloads only the Application's hash-bound package records, verifies every byte, atomically writes them into the
  private workspace, and then uses the existing closed local validator and protected status replay.
- No candidate code runs and no GitHub write occurs during recovery. A nonunique, changed, mismatched, unavailable, or
  non-Draft candidate fails closed.

## Missing local inputs

If no exact Draft can be recovered, a valid Submission V2 still does not cause the Builder to fabricate an Application
V3.1 review package, source assessment, security evidence, prototype state, trade capability, Fee V2 selection, test
result, or source identity. The diagnostic now directs the Applicant to the explicit advanced Application-input help
instead of repeating the same `--resume` command.

## Authority boundary

The patch can read and continue only an existing unreviewed Draft. It does not evaluate, accept, approve, deploy,
register, make available, route, sign, move funds, or launch a project. A new or updated GitHub Draft still needs the
existing exact fresh confirmation digest and the normal protected Applicant transport.

The bundled `publicationStateVerified: false` status is not proof that Hookbuilder `v0.11.1` is public. Protected CI,
the immutable tag and release assets, public API visibility, fresh installation, and a real Draft-only journey must be
verified separately after publication.
